# Pluox

## Описание

Pluox - это современное веб-приложение, построенное на микросервисной архитектуре. Проект организован как монорепозиторий, что обеспечивает удобную разработку и поддержку всех компонентов системы в едином пространстве.

## Структура проекта

```
apps/
├── frontend/  # Веб-интерфейс пользователя
├── backend/   # Бэкенд-сервис REST API
└── website/   # Публичный веб-сайт проекта
```

## Технический стек

### Основные технологии

- TypeScript
- Node.js
- NPM Workspaces

### Фронтенд

- React - библиотека для построения пользовательских интерфейсов
- React Router - маршрутизация в React-приложении
- TanStack Query - управление состоянием и кэширование данных
- CSS Modules - изолированные стили компонентов

### Бэкенд

- Node.js LTS - стабильная версия для серверной части
- SQLite - легковесная реляционная база данных
- REST API - стандартный интерфейс для взаимодействия с клиентами

### Инструменты разработки

- EditorConfig - поддержание единого стиля кода
- Git - контроль версий и командная разработка
- VSCode - рекомендуемый редактор кода
- ESLint - статический анализ кода
- Prettier - автоматическое форматирование кода
- Vitest - фреймворк для тестирования

## Быстрый старт

### Предварительные требования

- Node.js (версия указана в `.nvmrc`)
- npm
- Git

### Установка и запуск

1. **Клонирование репозитория**

```bash
git clone https://github.com/your-username/savee.git
cd savee
```

2. **Настройка Node.js**

```bash
nvm use  # Активация правильной версии Node.js
```

3. **Установка зависимостей**

```bash
npm install  # Установка всех необходимых пакетов
```

4. **Запуск приложений**

Для запуска фронтенда:

```bash
cd apps/frontend
npm run dev
```

Для запуска бэкенда:

```bash
cd apps/backend
npm run dev
```

Для запуска вебсайта:

```bash
cd apps/website
npm run dev
```

Более подробные инструкции по каждому приложению находятся в README.md в соответствующих директориях.

## Разработка

### Рекомендации по разработке

- Следуйте установленным правилам кодирования:
  - Отступы: 2 пробела
  - Максимальная длина строки: 100 символов
  - camelCase для имен переменных и функций
  - snake_case для констант
- Используйте строгий режим TypeScript (strict: true)
- Используйте type для типов и interface для интерфейсов классов
- Пишите понятные коммиты, следуя конвенции Conventional Commits

### Стиль кода

- Используйте линтеры и форматтеры кода
- Запускайте проверку типов перед коммитом
- Размещайте тесты рядом с тестируемым кодом в файлах \*.test.ts

### Полезные команды

```bash
npm run lint         # Проверка кода
npm run format       # Форматирование кода
npm run test         # Запуск тестов
npm run build        # Сборка проекта
npm run type-check   # Проверка типов
```

## CI/CD

Проект использует GitHub Actions для непрерывной интеграции:

- Автоматическая проверка типов при пуш-запросах
- Линтинг кода
- Запуск тестов
- Сборка проекта

Подробности настройки CI/CD можно найти в директории `.github/workflows`.
